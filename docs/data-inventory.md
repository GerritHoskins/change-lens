# Data inventory and deletion boundaries

I-13 / AC-22 / AC-23. This inventory describes the implementation, its external dependencies and, in the rows that say so, the IONOS deployment. It is not evidence that a backup service or identity provider has erased anything. Recheck it whenever a content store or processor is added, before real-client-data acceptance and before publishing privacy declarations.

## Retention contract

Documents and comparisons expire 30 days after last use. The owner-defined use events are opening a report/source and explicitly importing, comparing or reviewing. Background refresh, status checks, list requests, worker retries and extraction-cache reads never extend retention.

Each source and comparison has its own clock. A comparison open/review touches that comparison and its two input sources; a source open touches that source only. Import starts the new source's clock; a new comparison starts its own clock and touches the selected sources. Sources still referenced by a retained comparison remain available. Automatic expiry does not delete the project's name or client label. Explicit project deletion covers the entire project.

Existing rows whose last use was never recorded receive a one-time 30-day grace window when the new column is bootstrapped. This is a migration safeguard, not a claim of observed user activity. Subsequent restarts must not reset populated clocks.

The app sends explicit opening events separately from content GETs, including when the source is already held in memory. A failed opening event is shown as a load failure with Retry; the app does not silently pretend the retention timer was extended.

## Completion and operational boundaries

Primary deletion can report complete only after the database content graph and all selected object versions have been purged. A durable pending operation is not a completed deletion. Retry after transport failure must be idempotent and tenant-scoped.

Cleanup must run independently of the comparison queue; idle-worker reconciliation alone can starve under continuous load. Configure and supervise the maintenance process in the target environment before claiming automatic retention is active. No maintenance command in this work is authorized to run against existing user or production data.

An account-deletion acceptance record additionally needs public identity/session integration, Apple revocation where applicable, all account projects, tokens and personal metadata, the backup/PITR/snapshot evidence above and actual-app checks on both platforms. These are outstanding release gates; primary-storage tests do not waive them.
